Конвенции проекта лежат в справках — вызывай нужную перед работой с незнакомой частью, это дёшево:
- вёрстка блока (Blade, поля, SCSS, JS) — get_block_guide
- шаблон страницы — get_template_guide
- Blade-компоненты — get_component_guide
- серверная логика блока — get_action_guide
- картинки и файлы — get_media_guide
- сторонние библиотеки и подключение стилей и скриптов — get_assets_guide
- глобальные настройки сайта — get_settings_guide

Четыре правила, о которые чаще всего спотыкаются, — держи в голове всегда:
- Директивы Blade разрешены по белому списку, а не запрещены по чёрному: отклоняется всё, чего нет в списке — включая привычные @push, @stack, @forelse, @auth, @csrf, @class, @include и @props. @php … @endphp разрешён для вычислений в шаблоне. Полный список — в get_block_guide; получив отказ валидатора, убирай ровно те конструкции, которые он назвал, а не ищи ошибку в платформе.
- JS блока получает корень блока как el и вызывается для каждого экземпляра: ищи элементы через el.querySelector, а не document.querySelector. Обёртки у блока нет — каждый CSS-селектор начинай с префикса slug, иначе стиль применится ко всей странице.
- Шаблон без @yield('blocks') отрендерит пустую страницу.
- Сторонние библиотеки подключает только attach_library, а созданный action — только attach_action. Без них код есть, а на странице ничего не меняется.

Как устроен сайт на Templite — следуй этому, даже если пользователь не просил явно:
- Шапка и подвал — всегда Blade-компоненты (create_component), шаблон вызывает их тегом <x-cms::slug />. Не верстай шапку и подвал внутри шаблона или блока.
- Общие данные сайта — логотип, телефоны, email, адрес, соцсети, реквизиты — только глобальные поля (apply_settings_layout, в вёрстке $global['ключ']). Поля шаблона — лишь для того, что отличается между шаблонами.
- Любая серверная логика — выборка данных, внешние API, обработка форм — только в action. Blade блока лишь выводит $fields, $global и $actions.
- Блок с подключённым action не держи в кэше: после attach_action выключи кэш его экземпляров на страницах через set_block_cache. Ajax-вызовы action из JS (/action/{slug}) к блоку не подключаются и кэшу не мешают.
